# JobPath 全站测试方案

本方案用于开发回归、小组联调和课程验收，覆盖岗位收藏、归档、学习计划、AI、投递记录、面试、Offer及本地数据。每次修改应保留可重复的操作步骤、预期结果和实际证据。自动测试通过表示相应场景通过，真实模型质量、实际手机和系统下载目录另行验证。

## 测试目标与通过标准

1. 正常操作能完成“选岗位 → 备战 → 投递 → 面试 → Offer → 复盘”路线。
2. 收藏、归档、取消收藏含义明确；归档可找到和恢复，原任务与投递记录保留。
3. 同一事实在各视图一致，刷新、切目标、导入、并发保存后不丢失或串到其他目标。
4. AI成功、失败、延迟及同时操作均有真实状态，不覆盖其他结果，不重复发送同一正在执行的操作。
5. 桌面、平板和窄屏可读、可操作，少量数据与长内容均无整页横向溢出。

缺陷等级：P0为泄露或不可恢复的数据损坏；P1为主流程无法完成、保存丢失或状态错误；P2为可绕行的交互/展示问题；P3为不影响理解的细节。交付时P0/P1须清零，P2应修复或有明确记录和处理安排。

## 环境与数据准备

| 环境 | 设置 |
|---|---|
| 用户本机体验 | 固定127.0.0.1:5175，由启动网站.cmd运行 |
| 自动浏览器回归 | 5199测试服务，独立APP_DATA_DIR，内存招聘库，真实AI关闭 |
| 浏览器 | Chromium、Firefox、WebKit；本机Edge补充布局和流程检查 |
| 视口 | 320、390、768、1280/1440px；至少一个真实手机补充验收 |
| 用户数据 | 每个测试使用独立上下文和合成记录，不接入用户现有浏览器配置 |
| AI | 自动检查用模拟响应；后端用内存数据库及临时合成配置；真实Key由使用者自行配置与操作 |

准备下列数据组：空记录；两个不同目标及各自任务；包含已归档/取消收藏岗位的记录；待做/进行中/完成/暂缓任务；有多轮面试与阶段回退的申请；两份不同城市和薪酬口径的Offer；长标题和多段说明；超过1000条任务或较长对话的备份；缺字段/未来版本/悬空引用的错误备份。

合成记录统一使用“合成/示例/测试”名称。录屏和截图不得出现真实Key、认证头、用户联系方式或他人履历。

## 自动检查执行顺序

```powershell
npm ci
npm test
npm run build
```

首次配置浏览器运行环境：

```powershell
npx playwright install chromium firefox webkit
npm run test:e2e
```

本机已将测试浏览器安装在项目.local/pw-browsers时，在同一终端先设置：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.local\pw-browsers'
npm run test:e2e
```

只复测本轮问题：

```powershell
npx playwright test e2e/followup-audit.spec.mjs e2e/saved-workspace.spec.mjs
```

另外启动5175网站后，执行独立Edge检查：

```powershell
npm run test:workflow
npm run test:layout
```

这些脚本不是实际模型质量测试。失败先记录原因，修复后复测受影响场景；涉及存储、导航或共享组件时运行全套。不能仅调整预期文字让失败消失。

## 界面 可访问性与性能

| 编号 | 操作 | 验收重点 |
|---|---|---|
| UI01 | 全部标签、详情和弹窗按多视口截图 | 正文可读、无整页横向滚动、按钮和输入不被截断 |
| UI02 | 检查AI历史、面试卡片、复盘小节和筛选 | 同组文字间隔约8—12px；不同内容区约20—28px；不能把说明贴在下一模块上 |
| UI03 | 长标题、长公司名、多城市、多段AI建议 | 换行自然，按钮与元数据不重叠 |
| UI04 | 只用键盘操作主流程 | 焦点清楚，弹窗与浮动助手可关闭，标签可切换 |
| UI05 | 减少动态效果模式 | 内容和状态仍完整，位移动效停止，操作无需等待动画 |
| UI06 | 浏览器缩放到200%及真实手机打开 | 重点文字与按钮仍能访问；自动视口模拟不能代替实际触控检查 |
| PERF01 | 本地冷热启动各3次，记录首个可操作画面时间 | 建议目标为本地常规数据2秒内可操作；记录设备与实际值，不宣称已达到 |
| PERF02 | 1000条任务、1000条申请进行筛选和切页 | 建议交互完成目标300ms内；如超过，记录规模并考虑列表分页/虚拟化 |
| PERF03 | 多次开关助手、弹窗、切页并查看性能记录 | 不累积监听器、后台循环或持续内存增长；不将短时波动称作泄漏 |

性能目标属于验收参考，不是网站的调用次数、时间预算或用户记录上限。

## 安全与外部服务检查

- 用合成HTML和危险链接检查转义、HTTPS来源处理；输入不能执行脚本。
- 请求.env、.local、数据库和后端源文件应不可下载；跨来源配置写入应拒绝。
- 配置响应和个人导出不包含Key、认证头和令牌；测试不打印这些字段。
- 模拟供应商错误与真实供应商检查分开。真实Key由使用者自行填写，助手不读配置正文。
- 公开招聘页/资源链接抽样打开，记录核验时间；HTTP可访问不代表仍在招聘或项目已完整运行。
- 在真实浏览器确认文件最终出现在下载目录，并能手工导入。无头浏览器的原生下载完成事件在本机可能等待系统扫描，自动检查验证的是下载发起与应用生成的实际JSON字节。

## 课堂验收顺序

1. 功能：收藏岗位→归档找回→目标与任务→进度→模拟或真实AI→投递/面试→Offer。
2. 非功能：手机宽度、键盘操作、保存失败恢复、并发AI保存、坏备份保护。
3. 关键技术：原生模块化前端、Node本地服务、IndexedDB个人数据、SQLite调用/招聘记录、固定AI工作流和只读上下文工具。
4. 工作量：运行npm run count:source，说明统计口径；小组分工由成员自行补充。
5. 保存本次结果与待人工检查项，不能用旧报告替代本次执行。
