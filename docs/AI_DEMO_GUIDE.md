# AI功能展示指南

## 展示前准备

先启动网站，固定使用 http://127.0.0.1:5175 。设置→连接AI服务，填写从DeepSeek后台申请的Key，选截止日期和启用，点击验证连接并保存。网页负责配置已有Key，不能替供应商创建付费账户或新Key。验证调用官方/models接口，不生成答案；实际生成仍计费。密钥保存在本机服务端.local/ai-settings.json明文文件（本机权限可读），不回显、不进入浏览器数据或Git。共享电脑需保管该目录；设置保存后立即生效，不需重启。

先录入合成画像：Web前端、每周8小时、目标上海、实习、真实可用日。毕业日期用演示者选择的合成值，别伪装成本人经历。选择/录入一个目标岗位。真实演示前检查个人剩余次数：默认每天2次，四个AI场景需多个日期或事先在.env设置AI_DAILY_LIMIT=10再重启；全站预算不会因此重置。

## 8—12分钟推荐路线

| 顺序 | 操作与示例输入 | 展示的结果与解释 |
|---|---|---|
| 1 约1分钟 | 个人目标，选定前端目标 | 画像是所有AI任务的共享上下文 |
| 2 约2分钟 | 备战→AI个性化计划：“未来两周每周8小时，先做HTTP接口练习，给出具体日期、验收结果，每项30—60分钟” | AI返回最多7个重点节点，后端检查日期/容量/可用日，不是固定任务模板 |
| 3 约1分钟 | 展开生成计划，点采用为学习任务；展开我的学习计划，编辑一项为进行中 | 建议转为正式任务需本人确认，旧记录保留 |
| 4 约1分钟 | 实际完成后填成果与验证方式，标完成 | 演示用合成成果须明确说明。进度更新不等于系统运行过代码 |
| 5 约1分钟 | 规划助手：“今天只有45分钟，结合当前任务帮我安排，并说明下一步” | 一轮生成有画像、任务和最近对话，刷新保留最近记录 |
| 6 约2分钟 | 求职→投递顺序：“2027届，目标上海实习，每周能到岗三天，先给出需核实项，再按优先级推荐目录中的具体岗位” | 推荐有具体岗位、官网与核验时间；不补造截止日期，不是全网实时搜索 |
| 7 约2分钟 | 添加求职记录后，面试规划：“下周三技术面，帮我安排项目讲解、基础复习和面后复盘” | 选择建议采用为轮次，实际完成后编辑状态及经验；建议不当成已经面试 |
| 8 约1分钟 | 直接录入两份合成Offer，比较城市/工作内容/薪酬口径/回复日期 | Offer比较是结构化录入即时更新，不是模型猜测或企业自动同步 |
| 9 约30秒 | 设置→导出备份 | 保存个人学习、台账、AI结果；Key和邀请不包含在备份内 |

## 诚实说明框架

这是一个受控、一次调用的AI工作流：场景选择→只读上下文工具→场景prompt→模型JSON→业务校验→草稿展示→用户采用→本地持久化。没有安装多Agent框架，没有模型自主循环调用工具，也没有自动投递。四个工具由服务端按固定流程提供画像、任务、目录岗位和面试历史。workflow元数据仅记录模式、工具名、耗时，不记录密钥或用户正文日志。

相对通用聊天框，项目特色在上下文与业务动作的连接：计划能变成任务，建议能变成轮次，岗位ID能追溯目录，完成证据能影响下一次建议。

## 状态与失败演示

- AI未配置：展示设置页的未配置状态，不能把测试输出称真实AI。
- 密钥错误：验证失败不覆盖旧配置；输入保留，可重新填写。
- 生成失败/额度耗尽：说明已保留文字和历史，无自动付费重试。
- AI日期/容量不合理：结果在后端拒绝，不能直接写入不可执行任务。
- 岗位状态未知：说明AI建议是投递参考，须打开官网核对。
