| 顺序 | 操作 | 可展示的效果 |
|---|---|---|

| 2 | 备战学习任务：“两周内准备前端实习，每周8小时，安排接口练习和项目讲解，给出日期与验收结果” | AI生成个性化方案，保存到当前目标档案 |
| 3 | 采用为学习任务，打开其中一项更新状态与成果 | 建议进入正式任务，进度更新，原记录保留 |
| 4 | 切换“日程与计划”，查看任务日期，切换周；自定义周期让AI再规划 | 日期来自真实任务；手动排期与AI历史各自可查看 |
| 5 | 右下打开规划助手：“今天只有45分钟，结合进度给我安排，并解释优先级”；再补充一个条件追问 | 连续对话结合目标与任务，刷新后记录保留 |
| 6 | 求职→投递记录→展开AI投递建议：“上海实习，每周到岗三天，根据目录岗位推荐投递顺序和核实项” | 岗位来自目录，有具体官网来源，可加入投递记录 |
| 7 | 面试时间线输入“下周三技术面，安排项目讲解、基础复习与面后复盘”；采用建议并记录经验 | 建议关联已有申请，实际安排与完成状态可更新 |

| 9 | 数据管理导出备份，说明可恢复 | 学习、AI、申请、轮次、Offer统一保存，Key不在备份中 |

## 功能与关键技术

这是场景化的一次调用AI工作流：场景 → 只读上下文工具 → 独立prompt → 模型JSON → 结构与来源校验 → 展示 → 用户采用 → IndexedDB持久化。

后端四个工具为get_profile、get_learning_tasks、find_catalog_jobs、get_interview_history；由服务端固定流程收集，不是模型自主多轮调用工具的多Agent系统。个性化价值在于真实进度能参与后续建议，计划能转任务、建议能转轮次、目录岗位能进入投递记录。

网页：原生JavaScript ES模块与CSS响应式布局；本地服务：Node.js；个人记录：IndexedDB；AI调用记录和招聘记录：SQLite。备份沿用schemaVersion1，保留历史兼容。没有引入新的UI框架、日历库或动画依赖。

## 非功能展示

- 响应与效率：任务/资源/求职内容分标签，任务和长计划区内部滚动，手机没有整页横向溢出。
- 可用性：字号正常，键盘焦点清楚，弹窗Escape关闭，浮动助手可收起，加载及错误紧贴触发按钮。
- 数据可靠性：保存失败不当作成功；草稿可恢复；重复提交与重复采用不创建重复记录；坏备份不覆盖原记录。
- 密钥配置：密码输入、本机服务端保存、响应不回显、个人备份不携带。
- AI异常：可用模拟响应演示错误保留输入与重试按钮；不要为演示故意破坏自己的真实Key。

没有网站自创的调用次数、累计费用或试用到期门槛。真实供应商错误仍如实提示。

## 新增：岗位雷达与打卡动效演示

1. 设置里完善城市、求职类型、方向和可用时间；AI连接沿用你自己配置的服务。
2. 机会 → 探索岗位，补充“上海实习，已有响应式页面项目，希望补充项目实践”，点击AI匹配岗位。请求期间展示雷达，可收起继续浏览。
3. 返回后展示推荐理由、需补齐项和具体岗位来源；查看详情、收藏，再加入投递记录，说明仍是“收藏”阶段。返回已有岗位时不会重复新建申请。
4. 收藏岗位里设为目标，备战中生成学习计划并采用、完成一项任务。新的进度用于后续AI上下文。
5. 每日打卡保存后展示庆祝浮卡，刷新仍已打卡。月历日期格本身形成低频波浪。日期颜色缓慢流动，已打卡的绿色与当天轮廓保留。
6. 介绍岗位目录内匹配的范围，不声称实时全网检索、自动投递或精确匹配率。真实模型返回很快时雷达可能短暂出现，不人为延长等待。

自动回归使用合成响应，见MOTION_ACCEPTANCE.md；课堂若改用真实AI，展示内容由当次模型返回决定。

动效查看捷径：备战→每日打卡看日期格波浪（手机先展开日历）；机会→探索岗位→AI匹配岗位，处理中自动播放雷达；切换标签、打开规划助手、悬停岗位卡片查看交互过渡。无须点击动效开关或演示按钮。
