# 招聘详情优化：第 2～6 项

日期：2026-10-30。分支 tjj；保留深绿、米白、琥珀的现有风格。真实 AI 关闭，不部署，不合并 main。

## 改动

- 职位名称独立为 24px 主标题，公司、城市、招聘类型降为辅助行；去掉招聘卡片内英文栏目标题和螺丝装饰。正文桌面 16px、窄屏 15px，限制为 76ch 阅读宽度。
- 岗位介绍按工作对象、主要职责组织，关键要求下分申请资格和技能与能力。学历、毕业/学生身份、到岗频率/时长缺少明确摘录时显示未披露；不从职位名称或方向标签推断技能门槛。
- 显示层合并重复资格，保留原文中的“或、至少一种、优先”等条件。将旧目录以“还要求”开头的补充要求放入技能区，不冒充职责。仅有要求摘录时，工作对象和职责明确未披露。
- 对采集器的有界片段，未结束的最后一行不当作完整职责/要求展示；原始片段完整保存在可展开的来源区，并提示可能截断。不会补写残句或覆盖源数据。
- 招聘状态使用“核验时有投递入口 / 待核验 / 已截止”；旁边显示易读检查时间，详细依据与北京时间在折叠区。来源域名、官网标注日期、招聘单位与原始摘录在独立来源区，不把来源可信度等同于当前在招。
- 卡片顶部以官网查看/投递为主要操作，收藏为次要操作；动作栏在卡片内部滚动时固定可达。单位招聘主页放入来源折叠区，避免与职位投递入口竞争。
- 原地收藏、撤销、取消收藏、理想 JD 整理流程保持兼容。无新增真实 AI 调用；此轮没有重新抓取或宣称实时核验全部岗位。

## 来源处理边界

本轮使用已有目录及核验快照。分组为本地确定性显示规则，工作对象短语来自已有职责摘录；没有明确职责的旧岗位不补造职责。原始记录、核验快照和用户收藏数据均未重写。规则不替代阅读官网完整 JD，也不输出资格通过结论。
