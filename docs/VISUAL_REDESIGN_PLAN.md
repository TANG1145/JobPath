# 全站视觉与信息架构整改计划

状态：方案待评审，本轮未执行换肤、布局重构或字体替换。日期：2026-11-05。工作分支：work/prep-career-ai。本轮只增加AI配置与功能改进。

## 目标与判断

改成明亮、积极、易读的学生求职工作台。优先解决信息架构、页面长度和字号层级，再统一配色、圆角与组件。仅把背景调亮会留下混乱布局，因此必须按模块迁移。四个主入口保留，真实业务记录、状态与导出格式保持兼容。

建议主方向：浅暖白底、白色内容面、蓝绿色主色、少量杏橙强调。积极感来自清楚的下一步、可见完成反馈和足够留白，不靠大面积荧光色或装饰动画。

## 本轮实际检查范围

已打开并截图：机会、备战、求职、设置、独立探索页、画像弹窗与私人JD录入。结合源码检查岗位列表/详情、学习任务编辑、AI建议采用、面试轮次、Offer表格、备份及错误状态；后者以此前功能测试和源码检查为依据，未声称所有弹窗本轮都有新截图。1440×1000桌面空数据条件下，机会页面约1480px高、备战3537px、求职2483px、设置2219px。数字用于诊断，不是强行压缩到一屏。

抽取导航和主内容中小于12px的叶子文本，分别约12、63、27、23处。该计数包含装饰文字，不等同可访问性完整审计。截图与清单保存在本机 .local/design-audit/，未放进产品目录。

发现：

- 背景、侧栏、卡片接近同一暗绿色，层次依赖重边框。阴影、螺丝、扫描线与水晶球同时抢注意力。
- 英文编号、系统在线、型号、导航副标题和页脚标语占空间；有些“AI DISABLED”还是静态文案，可能与实际配置冲突。
- 字体混用系统中文、等宽英文，9—11px文字与大屏数字混杂，部分模块说明比功能本身更显眼。
- 首次进入备战没有目标，却先展示大仪表盘；任务、排期、AI计划重复表达“我要学什么”。
- 备战两列高度不均，右侧日历/准备差距/学习节奏留下左侧空白；AI助手需要滚很远才能找到。
- 求职先堆两个大AI输入框，台账反而在后面；面试同时存在于独立时间线和台账轮次，复盘有两套，Offer空态仍提示旧操作顺序。
- 设置既有网页AI配置，又有邀请与本地状态宣传面板，应合并实际配置与状态，旧高级入口收起。
- 主页面和explore.html形成两套探索方式与导航风格，返回路线不清楚。
- 画像把18方向兴趣分数、毕业信息与全部可用日堆进长弹窗；保存按钮不在初始视口。

## 全站统一设计规范草案

| 项目 | 建议值与规则 |
|---|---|
| 页面背景 | #F7F9FC，避免纯白大面积眩光；卡片#FFFFFF |
| 主色 | #177E89；主按钮白字，深浅色组合需实测对比度 |
| 标题/正文 | #182B3A / #344454；次级文字#607080，暂定色需验证 |
| 强调色 | #F4A340，仅小面积用于今天、重点行动；成功与失败有文字/图标 |
| 字体 | 系统中文无衬线，禁止正文等宽；只有代码/数字对齐场景可用等宽 |
| 字号 | 页面标题28—30，模块标题20—22，正文/表单16，次级文本14；产品常规文案不低于14 |
| 行高 | 正文1.6；表单标签1.4；不手动拉大英文字距 |
| 圆角 | 卡片16，按钮/输入框10，弹窗20；标签可用圆胶囊但不滥用 |
| 边框/阴影 | 1px浅灰边，轻阴影可选；移除双重描边、硬投影、螺丝和扫描线 |
| 间距 | 4/8/12/16/24/32/48阶梯；卡片24内边距、区块24间距 |
| 交互尺寸 | 输入/按钮44—48高；焦点清晰，键盘操作可达 |
| 内容宽度 | 约1280最大宽度；1600以上不把段落拉满全屏；表格可单独横滚 |

所有值先在“备战”验证，再扩展全站。圆角和大留白不能牺牲信息密度，信息丰富区域使用列表、表格与标签页，不使用无限卡片套卡片。

## 文案清理清单

删除：MISSION CONTROL、PWR、RESOURCE LIBRARY、SYS、LOCAL WORKFLOW、PERSONAL TERMINAL、型号001、无意义编号、重复品牌页脚和发光在线灯。

改名：备战控制台→我的备战；准备差距→任务进度；校准画像→个人目标；我的理想JD→收藏岗位；Offer事实对比→Offer对比；独立航行模式→删除。

保留：岗位来源/核验日期、未保存状态、失败原因、AI结果标签、未核实条件、导出备份与删除说明。保留这些信息但用正常字号、就近显示；长说明进入“了解更多”，不铺满每个卡片。状态必须来自实际数据，禁止写死“AI关闭”。

## 页面逐模块整改

### 全局外壳

- 侧栏只放品牌、机会/备战/求职/设置四项，最多一个帮助入口。取消导航英文副标题与编号。
- 顶栏只显示页面标题、必要的当前目标和主操作；不叠加系统眉题、口号和重复副标题。
- 首页缺目标时显示“先选择目标”引导；已有目标时默认进入今日任务。不要始终说“目标已锁定”。
- 将失败、加载、保存反馈归一为组件；会话结束不丢正式数据。

### 机会与独立探索

- 默认使用可搜索的18方向卡片/列表。水晶球若保留，仅放可选的“探索模式”，不承担主要找岗位任务。
- 筛选置于列表上方同一行：方向、城市、求职类型、搜索；窄屏进入筛选抽屉。
- 岗位表行优先显示职位、公司、地点、类型、信息状态；来源与日期在详情中清楚保留。
- 详情分“岗位与资格 / 原文与来源 / 个人备注”，底部主操作固定为收藏或设为目标。
- 主机会页与探索页共享视觉规范和返回入口；过渡阶段保留旧URL，防止历史链接失效。

### 备战

- 首屏：简洁目标概览+下一步操作；右上紧凑打卡日历。避免让日历高于整个目标任务区。
- 主区：今日任务/全部任务切换；列表显示标题、日期、预计时间、状态；点击打开侧面详情编辑证据。
- “学习计划 / 资源库 / 历史”作为二级标签，减少垂直堆叠。展开不无限加长页面，也不过度嵌套滚动。
- AI计划在计划页右侧或抽屉，生成建议与采用动作在同一视野。时间线显示任务日期、状态、来源。
- 规划助手使用可折叠侧栏，打开后有固定对话区和底部输入，避免为了等高制造大空白。
- 合并准备差距和学习节奏为简短统计；删除重复入口。

### 求职

- 二级标签“投递 / 面试 / Offer / 复盘”，默认投递。
- 投递表列：公司岗位、阶段、下一步、日期。AI投递建议以按钮打开建议区，不占满首屏。
- 面试展示按日期排序的轮次，可切即将面试/已完成；每轮挂准备、记录和经验。台账岗位详情引用同一轮次数据，避免两份记录。
- Offer使用结构化横向比较，缺失项显示待补充；可选择2—4个Offer。直录和从台账进入使用同一个表单。
- 当前进展与最近7天复盘合成一个模块，旧备注放归档区，用户可复制迁移。
- 不宣称自动收到公司Offer，不推算不存在的薪酬。

### 设置与表单

- 设置分“个人目标 / AI连接 / 数据管理”。AI只保留一个真实状态区，邀请作为高级选项收起。
- 画像表单分基础信息和高级偏好。日期选择用横向周日按钮组替代七行复选框；18方向兴趣放折叠高级区。
- 统一表单标签、帮助、错误位置，长表单底部固定保存按钮；删除数据使用专门确认界面。
- 空态给一个可执行入口；加载态不遮挡历史数据；错误不要求用户重新填写全部内容。

## 可验证的最终验收

- 1440、1280、768、390宽度无页面横向溢出，Offer表只在自身区域横滚。
- 普通常规文案不少于14px，正文16px；英文装饰眉题和编号清零。
- 对比度按WCAG AA检查，状态不只依赖颜色；所有交互支持键盘，弹窗焦点返回触发按钮。
- 首屏能回答“我在哪、当前目标是什么、下一步做什么”；单页只保留一个主行动。
- 所有原业务闭环、旧备份、AI停用、保存失败、空数据及长中文内容通过。
- 不以“页面更短”代替信息可达性；任何隐藏后的操作都能在最多两步内找到。
- 合成数据、真实API测试和真实用户记录分开；最终报告按课程功能/非功能/关键技术/工作量四部分呈现。

## 2026-11-05 优先级调整

用户明确要求先完善功能，风格另行讨论。本视觉方案现在为冻结状态，不执行配色、字体、圆角或大布局改造。此前各阶段的视觉值仅为备选讨论稿，不视为用户已批准。

前置主计划改为 [功能整理与稳定性实施计划](FUNCTIONAL_REORGANIZATION_PLAN.md)：先完成本机AI认证、任务/排期数据、建议与真实面试的边界、Offer/复盘统一，再讨论视觉实施。功能与视觉不能混在一次大提交里。该计划包含本轮已修复、已验证和待实施项，所有后续进度以它为准，本文只维护视觉待议内容。
