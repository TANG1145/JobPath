# JobPath 前端重塑分工文档

日期：2026-10-30　分支：`tb-dev`　配套说明：[前端重塑说明](FRONTEND_REDESIGN.md)

## 0. 先回答：重塑，还是大改？

**建议：重塑前端，不重写整个工程。**

| 方案 | 代价 | 风险 | 结论 |
| --- | --- | --- | --- |
| 只改配色/字体 | 2—3 天 | 主线仍然不突出，用户还是不知道先做什么 | 不够 |
| **重塑前端（当前 tb-dev）** | 约 2 周 | 低：领域、存储、后端、70 项测试不动 | **推荐** |
| 全量重写 React/TS/Workers | 4—6 周 | 高：测试、配额、AI 网关、备份全部要重做，60 人时预算会被吞掉 | 现在不做 |
| 继续加 AI 功能 | 每周增加入口 | 把"乱"放大，AI 变成第 5 个功能区 | 先收敛，再按上下文加 |

理由：

1. 这个工程最有价值的资产是**领域规则 + 70 项测试 + 配额/AI 网关**；问题集中在展示层和信息架构。
2. 它还没有完成，正是**前置改 IA/UI** 最便宜的时候；等 AI、复盘、Offer 都堆上来再改，返工面更大。
3. 前端重塑可以**保留旧的 `main`**，在 `tb-dev` 上并行验证；不合适当场丢弃，风险可控。
4. React/TS/Workers 是设计文档的目标架构，不是当前阻塞；等 UI 主线稳定后再立独立 ADR/里程碑。

**明确不做**：不换框架、不改 `state` 字段、不改 IndexedDB 版本、不改备份 schema、不改 `/api/*` 契约、不接真实 AI。这样本轮改动可以随时回滚到 `main`。

## 1. 目标与范围

### 本轮目标

- 用户首次进入 3 次点击内选定目标岗位。
- 每个页面只有一个主 CTA，AI 关闭时没有任何 AI 入口。
- 320/390/768px 无横向溢出；移动端有固定底部导航。
- 70 项单元/接口测试保持通过；24 条 E2E 在三浏览器通过；合并前只需整理证据。
- 旧备份仍可导入；不破坏 `state` 兼容性。

### 不在本轮

- 真实 AI 联调、公网部署、账号体系。
- React/TypeScript 迁移。
- 9 个 IndexedDB store 拆分。
- 新岗位/资源内容采集。

## 2. 角色与职责

沿用 PRD 的 A/B/C 分工，不新增角色。

| 角色 | 主责 | 本轮具体任务 | 决策权 |
| --- | --- | --- | --- |
| **A：产品 / 内容 / 用户测试** | 主线、文案、岗位与资源可信度、验收 | 写主线 spec；检查每屏只有一个主 CTA；校对空态/错误态/信任文案；组织 3 位学生任务测试；维护 PRD→实现状态表 | 主线与内容是否可发布 |
| **B：前端 / 设计 / 可访问性** | 信息架构、视觉系统、页面实现、E2E | `index.html`、`style.css`、`src/ui/*`、`src/app.js` 的视图与绑定；响应式；focus/键盘；E2E 维护 | 视觉与交互实现方式 |
| **C：平台 / AI / 安全 / 交付** | 状态与存储、AI 网关、配额、构建与 CI | 审核 `app.js` 的保存/并发逻辑；AI 可见性开关；时间数据修复；三浏览器 CI；备份兼容 | 数据安全与是否可合并 |

### RACI（关键事项）

| 事项 | A | B | C |
| --- | --- | --- | --- |
| 主线与页面优先级 | **R/A** | C | C |
| 视觉系统与组件 | C | **R/A** | I |
| 状态/保存/备份 | I | C | **R/A** |
| AI 入口与隐私文案 | **A** | R | **R** |
| E2E 与发布验收 | A | **R** | **R** |
| 合并 `tb-dev` | **A** | R | **R** |

R=执行，A=最终负责，C=被咨询，I=知会。

## 4. 文件所有权

| 路径 | 主 owner | 备份 owner | 规则 |
| --- | --- | --- | --- |

| `src/applications.js`、`drafts.js`、`storage.js` | C | B | 备份/并发相关，必须双审 |
| `backend/*`、`server.mjs` | C | — | 本轮不改 |

| `docs/*.md` | A | B | 状态变化当天更新 |

**共享文件修改规则**：`src/app.js` 由 C 主改；B 需要改绑定/视图时先发 diff；`style.css` 由 B 主改，C 不直接改样式。

## 5. 接口契约（改动前必须对齐）

### 路由

`#/opportunities`、`#/prepare`、`#/career`、`#/settings`。没有 hash 时：有目标进 `#/prepare`，无目标进 `#/opportunities`。

### 状态

`state` 字段不变：`direction/hours/tasks/jobs/applications/answers/ratings/events/checks`。新增字段只能是可选字段，且 `validateBackup` 能接受旧备份。

### 数据属性

`data-target-job`、`data-target-public`、`data-save-public`、`data-edit-job`、`data-apply-job`、`data-task`、`data-stage`、`data-editapp`、`data-round`、`data-offer`、`data-action`。新交互优先复用这些约定，避免每页一套。

### API

- `GET /api/health`：AI 开关与版本，决定 AI UI 是否可见。
- `GET /api/quota`、`POST /api/ai`：本轮不改。
- AI 关闭时不渲染任何触发按钮；开启时才显示设置页邀请与练习反馈。

### 文案

- 不用"100% 匹配""包过""一周拿 Offer"。
- 匹配分必须标"非录用概率"。
- 未知/待确认/未核验三种状态不能混写。
- 信任说明保留，但从首屏降级到折叠/详情。

## 7. 验收标准

### 产品

- 首次进入：机会页 → 选目标 → 备战页 ≤ 3 次点击。
- 无目标时不会生成计划；有目标时首屏只出现一个主 CTA。
- AI 关闭时全站无 AI 按钮；设置页能解释如何开启。
- 空态、失败态、保存态、过期态都有明确文案。

### 视觉/交互

- 每屏只有一个 amber 主按钮；其余为 secondary/ghost。
- 正文 15px 系统 sans；等宽只用于数字/状态/眉标。
- 无装饰性编号/SYS/版本号占用内容区。
- 320/390/768 无横向溢出；移动端底部导航可用。
- 键盘可走完选岗、计划、任务、投递；focus 可见。

### 工程

- `npm test` 70/70。
- `npm run test:e2e` 三浏览器全绿（合并前）。
- `npm run build` 通过，`dist` 不含密钥/后端。
- 控制台无 pageerror；无外部请求（AI 关闭）。
- 备份导出→导入→刷新语义一致。
- 旧备份可导入；旧任务重排不抛错。

## 8. 分支、评审与合并

- `main` 保持 v0.7 可回滚；`tb-dev` 只做前端重塑，不混入内容采集/后端改动。
- 一个 PR，标题：`feat(web): reshape frontend around target-job mainline`。
- 评审：B 讲 IA/视觉，C 讲状态/安全，A 讲文案/验收；至少两人 approve。
- 合并前：三浏览器绿、70 单测绿、构建绿、截图更新。
- 合并后：`main` 打 tag `v0.7.1-frontend`（或按实际版本），保留 `tb-dev` 一周用于回滚。
