# AI 增强阶段契约草案（未实现）

真实 AI 继续关闭。此文件是 A 阶段设计交付，不表示 F 阶段接口已可用。沿用 Node/SQLite 网关的身份、额度、幂等与超时处理；不以迁移基础架构扩大范围。

| 场景/version | 必需输入 | 结构化输出 | 事实保护 |
|---|---|---|---|
| jd-organize/v1 | JD 原文、snapshotId/version、允许字段枚举 | 要求草稿、原文引用、未知项、待核实问题 | 引用须在原文中；逐项确认后才创建新快照 |
| evidence-expression/v1 | 明确选择的 evidence IDs/revisions、岗位快照/要求、用途 | 表达草稿、每段事实引用、缺失信息 | 不补造指标；用户核实后才存材料新版本 |
| answer-feedback/v1 | 题目正文、turnId、答案 ID/version、评价维度、同意发送的摘要 | 引用片段、已覆盖、缺失、行动建议、可选追问 | 引用必须属于该答案；反馈绑定原版本，不改成果或评级 |

统一请求建议字段：scene、sceneVersion、contextVersions、idempotencyKey、consent、payload。服务端自行配置模型、固定 system 内容和上游，拒绝客户端任意 system prompt/upstream。校验长度、类型、来源引用与场景字段，不仅检查 JSON 可解析。

发送流程：准备输入 → 展示本次发送的全部字段、预算和额度 → 显式确认 → 发送中 → 成功或可解释失败 → 用户审阅 → 保存草稿或转为待确认行动。未确认的输出不得写为事实。请求和结果需要独立持久记录，离开页面后可以找回；本基础版尚无该 UI/数据表。

幂等键覆盖用户、场景和输入版本：相同键相同输入复用结果，不再次收费；相同键不同输入拒绝。预算先原子预留、完成后结算；超时状态与账单待定分开。取消前端等待不保证上游停止计费，文案必须明确。

练习预算按会话限制，包含最大输入、最大输出、累计费用与有限追问；数值须经最大输入测试和真实账单校准。基础版手动题目最多 20 轮只是本机 UI 防膨胀，不是 AI 额度承诺。

F 阶段需完成：三场景 Schema/模拟端到端、超时/坏 JSON/重复点击/并发/额度耗尽/陈旧上下文测试、结果回看和用户确认；固定不少于 20 个质量样本，覆盖缺上下文、矛盾事实、诱导虚构指标、无关回答、歧义要求。格式测试与人工内容评审分别报告。真实服务密钥、真实调用与账单仍需后续由用户授权配置。
