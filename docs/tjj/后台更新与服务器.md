# 应用内岗位更新与运行方式

本轮在 tjj 分支实现；不合并 main、不部署、不启用真实 AI。Codex 每日自动化已撤销，日程由 Node 应用自身执行。

## 后台每天 09:00

- `server.mjs` 启动后台调度器，每分钟检查北京时间；每天 09:00 领取当天任务。首次启动或停机后，只补最近一次应执行的日期，不追补所有历史日期。
- SQLite `.local/recruitment.sqlite` 保存岗位快照和执行记录；日期唯一键防重复启动。单进程不重叠执行；超过 20 分钟未结束的旧运行记录允许恢复。
- 采集在独立子进程执行，15 分钟超时停止。失败不会清空目录；失败访问会把岗位状态降为待核验，保留原内容与上次确认可投时间。当天失败可手动执行命令复核，自动任务次日再跑。
- Playwright 读取公开官网。需要登录、验证码或访问受限时不绕过。没有调用任何大模型。
- 当前新增发现适配百度日常实习公开列表首页，每轮最多 8 条；B站有公开详情链接时也会发现，当前页面不能解析时如实记录。其他公司目前对已收录官方详情做状态复核，不宣称全网实时全量抓取。
- 每轮最多核验 40 条，以较早核验的记录优先。官方链接、标题、明确结束标记和投递入口共同决定状态。HTTP 200 和搜索索引不等于在招；超过 48 小时的可投状态在界面自动降为待核验。
- 通过 `/api/recruitment` 提供只读数据；接口失败则使用同源的已发布快照。浏览器不直接爬官网，不上传私人 JD。
- 官网投递入口可用，仅代表核验时的页面证据，不保证接受申请或保证候选人资格。

## 本地运行

先安装依赖和浏览器：`npm install`、`npx playwright install chromium`。Linux 可用 `npx playwright install --with-deps chromium` 安装浏览器依赖。

`npm run dev` 启动应用及调度器。`.env` 中 `RECRUITMENT_AUTO_UPDATE=false` 可以禁用自动采集。需要代理时设置 `RECRUITMENT_PROXY`，不要把本机代理地址照搬到服务器。

`npm run recruitment:update` 手动采集，退出码 0 表示全部检查完成、2 表示部分来源待复核、1 表示运行失败。每次报告保存在 `.local/recruitment-report.json`。手动命令不修改用户收藏，也不自动提交 Git。

## 以后运行在服务器

小范围课程展示建议起步配置：2 vCPU、4GB RAM、40GB 以上磁盘，Ubuntu 24.04 x86_64。浏览器采集串行；无需 GPU。此配置是估算，尚未在该规格服务器实测。

同一台服务器运行 Node 应用、采集子进程和 SQLite。使用 systemd 保持 Node 运行及异常重启，Nginx/Caddy 提供 HTTPS 反向代理；按日备份数据库。服务器部署时还需要调整当前 localhost 的 host/origin 限制，此轮没有直接开放公网端口。

阿里云轻量应用服务器和 ECS 均可。三个月体验先比较学生券后 ECS 包月与轻量套餐总价。高校券为指定商品抵扣，不保证所有套餐可用；99元学生机不能叠加300元券。不要把首月促销价当作三个月总价。国内地域公开网站需备案；香港地域免内地ICP备案但可能增加价格和访问延迟。
