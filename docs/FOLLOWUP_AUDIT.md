# 归档与并发问题复查

日期：2026-11-05。覆盖用户提出的归档找回、名称理解、少量间距、全站回归与后续动效。所有测试使用独立合成记录，修改仅保存在本地分支。

## 发现与修复

| 问题 | 原因 | 修复 |
|---|---|---|
| 岗位归档后像消失 | 默认列表只显示正在考虑，归档入口藏在下拉筛选中，操作提示没有说明去向 | 新增正在考虑/已归档/全部收藏三个显式入口与数量；归档后可查看或撤销；空态说明记录所在位置 |
| 归档视图混入当前目标 | 原先置顶目标独立于筛选渲染 | 已归档视图只显示归档岗位，不再混入另一个正在备战的目标 |
| “投递台账”不易理解 | 使用偏管理场景的术语 | 页面与当前使用指南统一为“投递记录”，说明公司、岗位、阶段和下一步行动 |
| 少数小节贴得过近 | 目标标题无底部间距，AI历史方案没有分段容器，复盘与阶段历史共用默认标题间距 | 当前目标标题与卡片14px；历史方案分段；复盘、阶段历史与来源小节统一拉开，窄屏保持自然换行 |
| 同时生成计划和对话可能覆盖结果 | 两个回调都使用发起请求时的旧工作区快照 | 保存时读取当前目标的最新工作区，分别合并计划和消息；两种返回顺序均复测 |
| AI请求中刷新视图后按钮恢复过早 | 页面重新渲染创建了新的按钮，原按钮的disabled状态丢失 | 请求状态独立于DOM保存，重新渲染后仍显示处理中，完成后恢复 |
| 导入后旧AI结果仍提示完成 | 请求没有识别个人数据对象已被替换 | 旧响应不作用于新导入/重置的数据，并提示在当前数据重新生成 |
| 空白Offer或投递名称可保存 | 原生required只判空串，输入空格后trim得到空标题 | 保存时校验实际名称，保留输入供修正 |

归档不会删除岗位、任务或投递记录。归档当前目标会解除备战目标；普通恢复收藏不会擅自切换目标。立即撤销归档时，如尚未选择别的目标，可恢复原目标。
