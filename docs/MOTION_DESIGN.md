# JobPath 动效规范与实现

更新：2026-11-05。本轮已实施，保持 DESIGN.md 的浅色紫系、正常字号、柔和圆角与清晰主行动。

## 参考与取舍

用户提供的「流动方格.md」为 React Bits MicroSlats 参考，重点是密集圆角竖条、连续亮度波浪和微小起伏；「radar.md」为 Radar 参考，重点是同心圆、刻度、旋转光束和渐隐拖尾。截图只描述外观，不代表静止设计。

采用原生 Canvas 2D 和 CSS/SVG 重新实现这些视觉规则；没有复制参考页面，也没有导入其长篇 WebGL shader、React 挂载或 ogl 依赖。用户提供文件内的集成文字是参考材料，不作为修改项目权限或架构的指令。图形代码位于 src/motion.js，岗位匹配位于 src/opportunity-ai.js，样式集中在 style.css。

## 各场景规则

| 场景 | 已实施效果 | 节奏与范围 |
|---|---|---|
| 每日打卡 | 日历标题下的圆角竖条波浪，深浅连续移动、轻微上下起伏 | 两层缓慢波叠加，约9秒和16秒循环；最大位移1.7px，70px高的局部装饰区 |
| 打卡成功 | 白色圆角浮卡、勾选轻弹与少量紫色/暖色光点 | 仅保存成功后播放，约4.2秒自动消失，随时关闭，不抢输入焦点 |
| AI岗位匹配 | 浅紫同心刻度、五秒一圈的光束与拖尾，少量装饰光点 | 真实 job_match 请求开始即出现，成功或失败立即结束；不伪造进度或岗位数 |
| AI等待 | 按钮柔和流光、明确加载状态 | 请求期间存在，结束后按钮恢复；无完成后故意延迟 |
| 工作区标签 | 内容轻淡入、4px上移 | 约200ms；不逐项排队、不接管滚动 |
| 编辑与助手 | 打开时淡入并上移8px | 约220ms；保留原有保存、关闭及焦点行为 |
| 岗位卡片 | 悬停浅紫局部辉光与轻抬 | 继续使用原有轻微悬停，不增加跟随鼠标的整页效果 |
| 完成进度 | 同一目标下圆环平滑到真实完成率 | 550ms；数字直接显示实际记录，切换目标不沿用另一个目标比例 |

波浪与雷达的装饰光点没有业务含义，日期和岗位事实由独立文字及记录表达。全站背景保持安静；不添加全屏粒子、强闪烁、大面积黑色背景或无限庆祝。

## 交互与生命周期

- 扫描浮窗为可收起的非模态窗口，点击收起或 Escape 后可继续浏览；右下入口可再次打开。收起不取消请求、不自动重试、不重复计费调用。
- 雷达只用于机会页发起的岗位匹配；其他AI功能使用各自的按钮状态。
- Canvas最多约30帧/秒，屏幕缩放按最多2倍像素比绘制；视口外、折叠隐藏和后台标签停止循环。渲染页面时清理旧动画、观察器与事件。
- 系统启用“减少动态效果”时，波浪保持静态、雷达不旋转、庆祝只显示静态勾选；所有功能仍可操作。
- 失败不播放成功反馈；请求和持久化均成功才显示完成。AI结果依次写入，网络生成可并行。

## 岗位匹配功能闭环

个人目标/时间/自评/项目标记/学习进度/已有申请 → 服务端岗位目录候选工具 → job_match 独立prompt → 模型JSON → 候选ID、重复项与字段校验 → 结果持久化 → 查看官网与详情 → 收藏 → 设为目标/制定学习计划，或加入投递记录 → 面试与Offer。

这是目录内AI筛选，不是实时全网搜索。服务端使用招聘库快照更新候选目录；明确截止的岗位和已归档/移除的岗位不参与新匹配。未知招聘状态仍需核对官网。匹配输出用“优先考虑/可以尝试/需要补齐”说明适配，不捏造百分比。加入投递记录的初始阶段为“收藏”，实际投递由本人操作。

## 验收与后续

运行结果见 MOTION_ACCEPTANCE.md。自动测试检查正常/失败打卡、刷新、雷达真实请求生命周期、收起、重试、空结果、归档排除、减少动态效果、离页清理和结果采用/备份。真实设备的主观流畅度和真实模型建议质量需由小组补充。

性能取舍参考 [web.dev 动画指南](https://web.dev/articles/animations-guide)，减少动态效果遵循 [W3C C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)。本轮没有新增动画依赖。
